Unified native backing and independent calibration

Implemented behavior
--------------------
BackingPlayer uses one BackingSession for a full mix, one stem, or up to 32
sources (including the optional pristine full mix). Sources are decoded and
resampled on a worker into bounded aligned queues, mixed before one shared
Signalsmith stretcher and leveler, then sent through the selected native output.
At unity stem gains, an available aligned full mix plays alone; changing a stem
crossfades to the separated mix without replacing the transport. Missing or
misaligned optional full mixes retry the stems through the same native path.

A preparation worker owns creation, priming, cancellation and retirement.
Load/seek/rate changes use request generations and async N-API completion;
pause intent survives preparation. The callback retains a nonblocking try-lock,
never opens/decodes a file, waits for preparation, or destroys a session.
Fractional frame accounting supports noninteger speeds. Lookahead is prepared
before playback and the stretch tail drains before EOF. Decoder failure has an
explicit failed snapshot flag and stop-confirmed browser recovery.

Stems attempts native preparation before creating an AudioContext or fetching
browser PCM. Legacy/unsupported hosts retain browser compatibility. Native
analysis supplies a bounded read-only mono observation with output gains;
FFT runs in the renderer. Opening a reactive visualization does not require
browser playback. Consumers that explicitly require a live browser AudioNode
graph still use the existing compatibility handoff.

Timing contract
---------------
The legacy raw transport position and getTime remain for seek/loop control.
A nested version-2 presentation snapshot anchors the first rendered frame at
output callback entry. JUCE's reported output latency is applied once, without
adding another buffer period. Unknown driver latency is reported as unknown
and receives zero automatic correction; downstream TV processing is manual.

presentation = first-frame song position
             + (event time - callback entry - reported output delay) * rate
judgment     = presentation + song offset + (AV correction - input age) * rate

All differences in parentheses are physical seconds. Input processing is never
held waiting for output. The native verifier refreshes its reference when IPC
arrives and timestamps the input ring so worker/IPC scheduling delay is not
mistaken for physical input age. Extra source correction remains independent.
Default and custom highway renderers, NoteDetect, lyrics and rig timing use the
presentation contract. Metronome visuals follow presentation; click generation
keeps its scheduling clock. Native EOF retains its final anchor long enough for
a negative residual output calibration to finish, then bounds the chart at end.

Calibration profiles
--------------------
Desktop stores version-2 output/input profiles in slopsmith-audio-calibration.json
inside the current Electron profile. Keys include backend, actual opened device,
actual sample rate and buffer size, and input channel for input correction.
JUCE's portable API exposes exact device names; a future endpoint ID takes
precedence. Duplicate names produce session-only profiles that require recheck.
Default resolves to the actual device. Failed Apply attempts restore the prior
working route and never persist the rejected selection. Browser fallback keeps
the old global AV value separately. That old value is retained as migration
evidence and is not copied onto every native output. New native profiles start
at zero residual with a clear recheck label. Existing input correction migrates
only to the first input profile, also marked unchecked.

The Audio page shows the actual output setup and active AV correction after
Apply succeeds. Remember AV calibration per output setup defaults on. Turning
it off starts a shared native-output value at the current correction; later
changes save to that shared value. Turning it back on restores the current
device's saved profile. All device profiles and input correction are preserved.
The preference and shared value survive restart. Browser compatibility retains
its separate calibration. Failed preference writes leave the prior mode active.

Limits and validation
---------------------
Sources: 1-32 mono/stereo files, 8-384 kHz, positive duration up to 24 hours.
Queues default to 32768 frames and are bounded at 262144; prefetch depth is not
output delay. Speed is bounded at .01-4x. Source gains are finite 0-2.
Seek/resampler restart can change filter history; no claim of sample-identical
mixed-rate seeks versus uninterrupted playback is made.

Configure tests/native_backing with existing pinned JUCE_SOURCE_DIR and
SIGNALSMITH_STRETCH_DIR. Tests cover coherent queues/snapshots, real WAV/OGG
workers, full-mix/six-source parity, mixed rates, seek, cancellation, optional
full-mix validation, EOF, errors and concurrent capture/analysis observations.
BackingSession tests compare one and six sources at .5/.73/1/1.5/2/4x.
Core/Stems tests exercise exclusive ownership, controls, lazy fallback and no
browser allocation for native preparation. Timing tests include 2ms input and
-500ms output correction at different speeds, including the final output tail.
Profile tests cover restart, actual endpoint/format changes, ambiguity and failed
Apply rollback. Contract snapshots include the deliberate new API methods.

Physical acceptance still required
---------------------------------
Compare full mix, one stem and six stems on the same actual format/output, then
repeat on ASIO duplex and ASIO input plus Windows output. Verify input judgments,
pause/seek/loops/speed, final notes, visuals, faders, restart and profile restore.
Measure long-run underruns/dropouts separately from transition counters.
Editor/preview/metronome audio retains its existing renderer capture route;
this change unifies backing playback, not every sound source in the app.
No end-to-end device latency or TV-delay reduction is claimed by software tests.
